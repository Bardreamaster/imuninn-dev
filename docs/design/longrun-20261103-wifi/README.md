# 长时测试 2026-11-03（第二轮）：3 小时 Wi‑Fi，画面有运动，持续充电

**条件**：iPhone 17 Pro，Release 包；数据走 Wi‑Fi（PC 连 10.127.53.249），手机用充电头供电（不接 Mac）；镜头对着有运动的画面；`dataset` 预设（位姿 60 Hz、IMU 100 Hz、1920×1440@60 H.264 目标 12 Mbps、深度 60 Hz）。起点是上一轮刚结束，手机还是热的（fair）。1080 行，每 10 s 一行。

**结果**（`summary.json`、`longrun.png`）

| 项 | 结果 |
| --- | --- |
| 热状态 | 开始 fair（余温），**10 min 后降回 nominal，之后 170 min 一直 nominal** |
| 视频码率 | 平均 2.2 Mbit/s，峰值 16.8 Mbit/s（画面运动时） |
| 帧率（PC 端 10 s 窗口均值） | 位姿 60.0、视频 60.0、深度 60.0、IMU 99.8；最低窗口 53–54 |
| 丢帧 | 视频 252 / 65 万帧（0.04%），位姿 38，IMU 65，深度 0；编码器 0 |
| 电量 | 100% 全程（充电头） |

**对比第一轮（USB 连 Mac、静置）**

- 第一轮 75 min 后进入 fair 并一直保持；这一轮拔掉 USB 数据线后 10 min 内就回到 nominal，并且在码率高得多的情况下保持了 3 小时。说明第一轮的发热主要来自 **USB 连接 Mac 时的充电 + 数据链路**，而不是采集本身；日常用 Wi‑Fi + 充电头反而更凉。
- Wi‑Fi 的丢包比 USB 多（视频 0.04% vs 0.008%，位姿 / IMU 出现少量 UDP 丢包），都在可接受范围，帧率没有可见下降。

**结论**：手机在 Wi‑Fi + 充电头下全流采集 3 小时无降频、无热限制；USB 直连 Mac 更适合低延迟但会更热。
